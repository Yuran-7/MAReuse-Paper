\begin{abstract}
Multi-agent large language model (LLM) systems improve complex problem solving through role specialization and coordinated workflows. In multi-agent workflows, agents collaborating on the same task often process overlapping contexts. This overlap leads to substantial redundant computation and inference latency: prefill repeatedly recomputes KV caches for shared context, while decoding generates similar token sequences autoregressively. Existing computation reuse techniques have two key limitations. KV cache reuse methods for prefill selectively recompute a small subset of tokens based on KV deviations observed at the first LLM's layer, which poorly predict errors in later layers. Meanwhile, decoding-stage reuse across agents remains largely underexplored. We propose \textbf{MAReuse}, a computation reuse framework for multi-agent LLM inference that exploits structured redundancy across prefill and decoding. During prefill, MAReuse not only performs an initial token selection based on first-layer KV deviations but also re-selects critical token positions at an intermediate filter layer, so that the selected positions better capture KV errors in later layers. During decoding, MAReuse performs collaborative speculative decoding using exact history matches and a fallback logits-cache tree, enabling multiple draft tokens to be verified in a single forward pass. We evaluate on three diverse public benchmarks. While maintaining comparable accuracy, MAReuse delivers the lowest prefill and decoding latency among the evaluated KV-cache reuse and speculative decoding baselines, respectively. Compared with standard multi-agent inference, MAReuse achieves up to 2.7$\times$ prefill speedup and 3.2$\times$ decoding speedup.
\end{abstract}

\section{Introduction}

Recent LLM-based systems increasingly employ multiple collaborating agents to improve their ability to solve complex tasks. These agents can assume specialized roles, exchange intermediate results, and combine outputs produced throughout a structured workflow \citep{DBLP:conf/nips/LiHIKG23, DBLP:conf/iclr/ZhangYLYWWCY025}. When multiple agents collaborate toward a shared goal, their coordination naturally creates overlap in the information they process, as each agent repeatedly consumes the common task description, shared evidence, and intermediate outputs produced by other agents. This repeated processing leads to redundant computation and increased inference latency.

%Existing work on accelerating multi-agent inference focuses on reducing prefill overhead through KV cache reuse. Prefix caching works only for identical prompt prefixes \citep{DBLP:conf/sosp/KwonLZ0ZY0ZS23, DBLP:conf/nips/ZhengYXS0YCKSGB24}, which are easily invalidated when dynamically generated agent outputs are inserted at different positions. Non-prefix methods relax this restriction by using RoPE~\citep{DBLP:journals/ijon/SuALPBL24} to reposition cached keys across agent prompts before concatenation~\citep{DBLP:conf/fast/LiuG0WX0GHM26}. After RoPE alignment, selective correction methods recompute a subset of tokens to improve reused KV states. However, their token selection typically relies on first-layer KV deviations, and the selected positions remain fixed across later layers~\citep{DBLP:conf/eurosys/YaoLLRCZD0J25}. We observe that high-deviation tokens shift across layers; a fixed shallow-layer selection may therefore miss later-layer errors and degrade accuracy.

Existing work on accelerating multi-agent inference has primarily focused on reducing prefill overhead through KV cache reuse. One line of work employs prefix caching, which directly reuses KV states for identical prompt prefixes~\citep{DBLP:conf/sosp/KwonLZ0ZY0ZS23, DBLP:conf/nips/ZhengYXS0YCKSGB24}. However, this approach is difficult to apply to multi-agent workflows because dynamically generated outputs are often inserted at different positions, easily breaking prefix identity. To support reuse across non-identical prompts, non-prefix methods use RoPE~\citep{DBLP:journals/ijon/SuALPBL24} to reposition cached keys before concatenating KV states from different agent prompts~\citep{DBLP:conf/fast/LiuG0WX0GHM26}. Because the aligned KV states may still be inaccurate, subsequent methods selectively recompute a subset of tokens to correct reuse errors. Nevertheless, these methods typically select tokens according to first-layer KV deviations and keep the selected positions fixed throughout the remaining layers~\citep{DBLP:conf/eurosys/YaoLLRCZD0J25}. Our analysis shows that high-deviation tokens vary substantially across layers, suggesting that a fixed selection derived from shallow-layer signals may overlook critical errors in later layers and consequently degrade accuracy.

Beyond prefill, repeated generation patterns in multi-agent workflows also create opportunities to accelerate the decoding stage. Speculative decoding accelerates autoregressive generation by constructing a draft of multiple candidate tokens and verifying them in parallel with the target model in a single forward pass~\citep{DBLP:conf/icml/LeviathanKM23}. Such drafts can be retrieved from two complementary sources in multi-agent systems: \textit{in-sample cross-agent history}, generated by different agents on the current task, and \textit{cross-sample role-aware history}, generated by the same agent on previous tasks. However, existing retrieval-based methods~\citep{DBLP:conf/acl/HuWZZLCZ25, zhang2026racer} do not jointly exploit both sources, causing long exact continuations to be missed and forcing more frequent use of shorter drafts. This reduces the mean accepted tokens per verification step (MAT) and limits decoding throughput.

%Here, in-sample cross-agent history refers to earlier agent outputs generated while solving the same task, whereas cross-sample role-aware history refers to outputs produced by the same role on previously completed tasks. Both sources can provide long exact matches that form linear drafts, allowing speculative decoding~\citep{DBLP:conf/icml/LeviathanKM23} to advance generation by many tokens in a single verification pass. However, existing retrieval-based speculative decoding methods \citep{DBLP:conf/acl/HuWZZLCZ25, zhang2026racer} are not designed to jointly exploit both history sources in multi-agent workflows. Consequently, missed long-span continuations force more frequent fallback to shorter drafts, reducing mean accepted tokens per verification step (MAT) and overall decoding throughput.

To address these limitations, we propose \textbf{MAReuse}, a computation reuse framework that accelerates both prefill and decoding in multi-agent LLM inference. During prefill, MAReuse adaptively refines token selection at an intermediate layer, enabling more accurate correction of reused KV states in later layers. During decoding, it hierarchically retrieves draft sequences from in-sample cross-agent and cross-sample role-aware histories, and falls back to a logits-cache tree when no reliable match is found.

The contributions of this work are summarized as follows:
\begin{itemize}
	\item We propose \textbf{MAReuse}, the first computation reuse framework, to the best of our knowledge, that jointly accelerates both prefill and decoding in multi-agent LLM inference.
	
	\item We introduce filter-layer corrected KV reuse for prefill and collaborative speculative decoding for generation, exploiting the distinct reuse opportunities in the two stages. 
	
	\item Extensive experiments on three datasets and varying workflow widths demonstrate that MAReuse achieves average speedups of 2.00$\times$ in TTFT and 2.57$\times$ in decoding, while largely preserving task accuracy.
	
%	\item We develop filter-layer corrected prefill reuse to accelerate prefill and collaborative speculative decoding to accelerate decoding, addressing the distinct reuse opportunities in the two stages.

\section{Related Work}

\subsection{LLM-Based Multi-Agent Collaboration}

LLM-based multi-agent systems commonly use role-based interaction as the basis of collaboration. Different agents are assigned specialized responsibilities or perspectives, which guide task decomposition, information exchange, debate, and result aggregation. Representative systems include CAMEL, ChatDev, and MAD \citep{DBLP:conf/nips/LiHIKG23, DBLP:conf/acl/QianLLCDL0CSCXL24, DBLP:conf/emnlp/Liang0JW00Y0T24}. Later work further studies workflow orchestration and communication structure. AutoGen supports configurable message passing and dialogue control, while MetaGPT encodes structured multi-agent workflows through standard operating procedures \citep{DBLP:journals/corr/abs-2308-08155, DBLP:conf/iclr/HongZCZCWZWYLZR24}. GPTSwarm and AgentPrune further model and optimize information flow through graph structures \citep{DBLP:conf/icml/ZhugeWKFKS24, DBLP:conf/iclr/ZhangYLYWWCY025}.

\subsection{KV Cache Reuse}

KV cache reuse is an important direction for reducing LLM prefill cost. Prefix caching reuses previously computed KV caches when requests share an identical prompt prefix; vLLM and SGLang support efficient prefix sharing with PagedAttention and RadixAttention, respectively \citep{DBLP:conf/sosp/KwonLZ0ZY0ZS23, DBLP:conf/nips/ZhengYXS0YCKSGB24}, and RAGCache extends this to retrieval-augmented generation \citep{DBLP:journals/tocs/JinZJLLLJ26}. These exact methods are limited by strict prefix matching. To reuse non-prefix content, TurboRAG stores KV caches for retrieved documents, while APE uses adaptive parallel encoding and lightweight calibration to approximate sequential prefill \citep{DBLP:conf/emnlp/LuWRCT25, DBLP:conf/iclr/0002CC25}. Selective correction methods further trade off efficiency and quality: CacheBlend selects tokens by first-layer KV deviations \citep{DBLP:conf/eurosys/YaoLLRCZD0J25}, EPIC heuristically recomputes the first few tokens of each block \citep{DBLP:conf/icml/HuHWWHZFCS025}, KVShare shares KV caches across requests with dual-stage high-deviation recomputation and cache-aware scheduling \citep{DBLP:journals/corr/abs-2503-16525}, RelayCaching profiles layer ranges and sparse positions for multi-agent decode-to-prefill reuse \citep{DBLP:journals/corr/abs-2603-13289}, and KVCOMM estimates prefix-conditioned KV offsets with an online anchor pool \citep{ye2026kvcomm}. Query-aware token selection methods such as $A^3$ and ProphetKV are mainly designed for RAG scenarios, where the user query is usually placed at the end of the prompt \citep{DBLP:journals/corr/abs-2511-17560, DBLP:journals/corr/abs-2602-02579}; this differs from our interleaved multi-agent prompts.

\subsection{Speculative Decoding}

Speculative decoding reduces serial autoregressive steps by generating draft tokens and verifying them in parallel with the target model. Training-free methods retrieve candidates from repeated prompt fragments, as in Prompt Lookup Decoding \citep{saxena2023promptlookup}, or improve candidate construction with logits and automaton indices: Token Recycling builds logits trees from top-$k$ candidates, SAM-Decoding retrieves suffix-automaton matches, and RACER combines logits trees with Aho-Corasick retrieval \citep{DBLP:conf/acl/LuoWZZZ0X25, DBLP:conf/acl/HuWZZLCZ25, zhang2026racer}. These methods improve draft coverage but mostly target single-request or single-agent contexts. Model-based methods such as EAGLE-3 and DSpark train dedicated draft components \citep{DBLP:conf/nips/LiWZZ25, cheng2026dspark}; in contrast, MAReuse requires no additional model training and constructs drafts from in-sample cross-agent outputs and cross-sample role-aware history.


\section{Preliminaries and Observations}

\subsection{Preliminaries}

We represent a multi-agent inference workflow as a directed acyclic graph $G=(V,E)$. Each node $v\in V$ corresponds to an agent invocation, while each edge $e\in E$ represents the transfer of generated text from a predecessor node to a successor prompt. The prompt of node $v$ can be written as an alternating sequence of static template segments and dynamic placeholders:
\begin{equation}
	P_v = a_0 \cdot z_1 \cdot a_1 \cdot \ldots \cdot z_m \cdot a_m,
	\label{eq:prompt-decomposition}
\end{equation}
where $\cdot$ denotes concatenation of prompt segments, $a_i$ denotes fixed role instructions, few-shot examples, or template text, and $z_i$ denotes dynamic content such as the user question, predecessor outputs, or auxiliary conditions. Since node outputs are inserted into successor prompts, previously processed text is repeatedly encoded by downstream nodes. For a chain of $M$ calls whose accumulated context grows by an average of $L$ tokens per call, the total prefill token-processing volume is approximately $O(\sum_{i=1}^{M}iL)=O(M^2L)$. If each call generates an average of $Y$ tokens, the workflow also performs $O(MY)$ autoregressive decoding steps. Despite this linear scaling, decoding remains a major latency bottleneck because token generation is inherently sequential.

\subsection{Observation 1: High-Deviation Token Sets Vary Shift Across Layers}

As discussed above, the same output can have different KV states under different prefixes, making direct KV-cache reuse across agents inaccurate. Selectively recomputing the KV state of a few influential tokens can reduce deviations from full-prefill KV states and better recover attention across prompt segments. A representative token selection method is CacheBlend \citep{DBLP:conf/eurosys/YaoLLRCZD0J25}, which ranks reused tokens by K or V deviation. For a comparison layer $\ell$ (with layers indexed from 0), let $\tilde V_i^\ell$ denote the value state obtained by direct cache concatenation without token recomputation, and let $V_i^\ell$ denote the exact value state under the current full prompt. We use value deviation to define the selected set:
\begin{equation}
\mathcal S_\ell =
\operatorname{Top}_{\rho}
\{\|V_i^\ell-\tilde V_i^\ell\|_2^2\}_i .
\end{equation}
Here $\operatorname{Top}_{\rho}$ returns the top-$\rho$ fraction of reused-token indices. The same definition can be applied with key deviation. CacheBlend selects $\mathcal S_1$, i.e., the tokens with the largest layer-1 deviation, and uses this fixed set for recomputation in all later layers. We conduct this analysis on HotpotQA~\citep{DBLP:conf/emnlp/Yang0ZBCSM18}, one of the datasets used in CacheBlend's analysis. We evaluate the consistency of token selection across layers by comparing $\mathcal S_1$, $\mathcal S_6$, and $\mathcal S_{16}$ with $\mathcal S_f$ at comparison layers $f\in{4,6,16,24}$. With $\rho=20\%$, consistency is measured by Jaccard similarity. If layer-1 deviations were reliable proxies for later-layer deviations, $\mathcal S_1$ would maintain high overlap with the selected sets at middle and deep layers.

\subsection{Observation 2: Multi-Agent Outputs Exhibit Long Exact-Match Spans}

To conservatively estimate reuse opportunities during decoding, let $Y=(y_1,\ldots,y_n)$ be an agent output sequence and let $S$ be a candidate source sequence, such as prior agent outputs, few-shot examples, or the user question. For each $i\in\{1,\ldots,n\}$, $L_i$ denotes the longest exact contiguous span starting at $i$ that also appears in $S$:
\begin{equation}
L_i=\max\{\ell \mid \exists j,\;Y_{i:i+\ell-1}=S_{j:j+\ell-1}\}.
\end{equation}
Here $j$ indexes the matching start position in $S$, and $\ell$ is the length of the exact match.
The coverage by spans of length at least $k$ is
\begin{equation}
\begin{gathered}
\mathrm{Coverage}_{\ge k}(Y,S)
=\frac{1}{n}\left|\bigcup_{i:L_i\ge k} A_i\right|,\\
\text{where } A_i=[i,i+L_i-1]\cap[1,n].
\end{gathered}
\end{equation}

Moreover, reuse opportunities increase consistently with workflow width, with $\mathrm{Coverage}{\ge16}$ reaching 12.0\%, 18.2\%, and 21.1\% for workflows involving 3, 4, and 5 agents, respectively.

\subsection{Overview}

	\caption{Overview of MAReuse. The framework reuses aligned KV caches during prefill with filter-layer correction and accelerates decoding with verifiable drafts from local outputs, role-aware history, and logits-cache trees.}
	\label{fig:mareuse-overview}
\end{figure*}

Figure~\ref{fig:mareuse-overview} illustrates the overall workflow of MAReuse. Given a fixed multi-agent workflow, MAReuse accelerates inference without adding a draft model or changing the generation policy. As agents execute, they produce token sequences along with reusable byproducts of target-model computation, including KV caches, auxiliary hidden states, and logits from verified decoding steps. Token ids provide the sequence anchors for both prompt reconstruction and history matching; KV caches, together with hidden states, help avoid redundant prefill computation; and cached logits provide alternative next-token candidates for constructing fallback tree drafts. 

\subsection{Prefill Reuse with Filter-Layer Correction}

Following the prompt decomposition in Eq.~\eqref{eq:prompt-decomposition}, MAReuse precomputes KV caches for static segments $a_i$ during graph initialization and stores the caches of user questions, agent responses, and generated conditions as they become available during execution. To construct the prompt for node $v$, it retrieves and concatenates the required token IDs and KV caches, then realigns each chunk to its new position by adjusting its RoPE rotations, following the standard practice for non-prefix KV reuse. After positional realignment, a subset of tokens is selected for recomputation under the assembled prompt. However, \textbf{Observation 1} shows that selecting this subset only from layer-1 deviations, as in CacheBlend, can miss tokens that become important in later layers.

MAReuse addresses this issue with filter-layer correction. A straightforward approach is to choose a filter layer $f$, fully recompute all tokens at every layer preceding $f$, and then re-select tokens at layer $f$ according to their KV deviations. To avoid recomputing all layers before $f$, MAReuse records the input hidden states of layer $f-1$ when a reusable segment is first produced, together with its token IDs and KV cache. During reuse, it applies RoPE alignment, selects high-deviation tokens at layer 1, and propagates only these tokens to layer $f-1$. It combines their updated hidden states with stored states for the remaining tokens and recomputes all tokens in the full sequence at layer $f-1$. The resulting hidden states produce KV states at layer $f$, which are compared with the concatenated reused KV states. Based on these deviations, MAReuse re-selects the tokens to be recomputed from layer $f$ onward, while the remaining tokens continue to use their aligned cached states.

We quantitatively analyze the reduction in KV deviation achieved by different filter layers and select the most suitable layer through offline experiments. Here, $V_i^\ell$ and $\tilde V_i^\ell$ have the same meanings as defined in \textbf{Observation 1}, while $\tilde V_i^{\ell,(f)}$ denotes the value state after correction using candidate filter layer $f$. We measure the overall deviation reduction as:
\begin{equation}
	\begin{aligned}
		G_\ell
		&=\frac{1}{n}\sum_{i=1}^{n}
		\|V_i^\ell-\tilde V_i^\ell\|_2^2,\\
		G_\ell^{(f)}
		&=\frac{1}{n}\sum_{i=1}^{n}
		\|V_i^\ell-\tilde V_i^{\ell,(f)}\|_2^2,\\
		\mathrm{Reduction}(f)
		&=\frac{\sum_{\ell\in\mathcal L}
			(G_\ell-G_\ell^{(f)})}
		{\sum_{\ell\in\mathcal L}G_\ell}.
	\end{aligned}
\end{equation}
We set $\mathcal L$ to all model layers and report the overall reduction for each candidate in Figure~\ref{fig:filter-layer-sweep}. In particular, $f=1$ corresponds to layer-1 correction and is shown as the dashed line. The filter layer with the largest reduction is selected and fixed during inference.

\subsection{Collaborative Speculative Decoding}

\subsubsection{Local Retrieval with a Dynamic Suffix Automaton}

MAReuse constructs speculative drafts from multi-agent generation histories whose tokens have already been generated or verified by the target model. \textbf{Observation 2} shows that multi-agent outputs contain many long exact reuse spans, especially reusable intermediate content generated by other agents earlier within the same sample. To capture these local reuse opportunities, MAReuse uses a dynamic suffix automaton (SAM) as the local index.

A suffix automaton compactly represents all substrings of the inserted token history and supports online fallback through suffix links to find the longest available match. The SAM is initialized empty at the start of each sample and released after the sample finishes, restricting the local index to current-sample histories. At each speculative decoding step, MAReuse queries the SAM for the longest in-sample suffix match and uses the following tokens as a linear draft; after verification, the accepted tokens are inserted back into the SAM. This dynamic-anchor design avoids committing to a fixed anchor length: short fixed anchors are easy to match but weakly constrained, while long fixed anchors impose strict matching requirements and may miss reuse opportunities. As shown in Table~\ref{tab:local-sam-ablation}, dynamic matching outperforms fixed $n$-gram anchors in throughput and MAT.

\subsubsection{Role-Aware Global Retrieval}

Motivated by \textbf{Observation 3}, MAReuse queries a role-aware global index after a local miss. The global index is implemented as a hash table whose hash key consists of the role, anchor length, and exact anchor tokens. Each hash key maps to a bounded list of source-span references rather than duplicated continuation tokens. Outputs from completed samples are enumerated with three fixed anchor lengths and committed to their role-specific partitions. During lookup, MAReuse tries longer anchors first and selects a referenced continuation using lightweight evidence such as historical hits, recency, and continuation length. We provide a TTL-based pruning mechanism for memory control. Each anchor records its last query access, and periodic pruning removes anchors that remain inactive beyond a configurable window; both the inactivity threshold and pruning interval are adjustable.

\subsubsection{Logits-Cache Tree Fallback}

MAReuse prioritizes linear drafts retrieved from local and global histories because an exact match may allow a long token sequence to be accepted in a single verification pass. When no valid linear draft is available, MAReuse deterministically falls back to a logits-cache tree draft, as illustrated in Figure~\ref{fig:tree-draft}. The cache maps each verified token ID to its top-$k$ next-token IDs. Starting from the current token, the module fills a fixed tree template by looking up each node token and placing its cached successors at adjacent child nodes. For each verification pass, MAReuse derives the tree attention mask and position IDs from this adjacency and uses leaf retrieval indices to recover candidate paths after target-model verification. Posterior verification then selects the accepted path; if all predictions on a branch are accepted, the draft can accept all tokens along the root-to-leaf path in a single pass.

As with the global index, we provide an optional pruning scheme to control the logits-cache tree size. Tree size determines how many candidate branches one verification step can cover: Larger trees may increase MAT but also raise the cost of each verification forward. MAReuse starts with a large template, records target-model-verified paths from early samples, and greedily retains nodes covering frequent historical paths. The resulting smaller template is frozen for subsequent samples.

\section{Experiments}

\subsection{Experimental Setup}

\textbf{Datasets and Models.}
Following KVCOMM~\citep{ye2026kvcomm}, we evaluate MAReuse on multi-agent systems across three benchmarks: GSM8K~\citep{DBLP:journals/corr/abs-2110-14168} for mathematical reasoning, MMLU~\citep{DBLP:conf/iclr/HendrycksBBZMSS21} for knowledge question answering, and HumanEval~\citep{DBLP:journals/corr/abs-2107-03374} for code generation. GSM8K and MMLU use Llama-3.1-8B-Instruct, while HumanEval uses Qwen2.5-Coder-7B-Instruct. Experiments are implemented with PyTorch 2.11.0 and Transformers 4.50.2 and conducted on an NVIDIA GeForce RTX 4090 GPU. Unless otherwise stated, all methods use the same multi-agent workflow and greedy decoding.

\noindent\textbf{Baselines.}
For prefill, Full Prefill denotes standard prefill without KV reuse, while MAReuse-P denotes MAReuse with only prefill reuse. We compare MAReuse-P with CacheBlend~\citep{DBLP:conf/eurosys/YaoLLRCZD0J25}, EPIC~\citep{DBLP:conf/icml/HuHWWHZFCS025}, RelayCaching~\citep{DBLP:journals/corr/abs-2603-13289}, and KVCOMM~\citep{ye2026kvcomm}. For decoding, Autoregressive denotes standard target-model decoding without speculation, and MAReuse-D denotes MAReuse with only collaborative speculative decoding enabled. We compare MAReuse-D with retrieval-based speculative decoding methods that do not require an auxiliary draft model: Token Recycling~\citep{DBLP:conf/acl/LuoWZZZ0X25}, RACER~\citep{zhang2026racer}, and SAM-Decoding~\citep{DBLP:conf/acl/HuWZZLCZ25}.

\noindent\textbf{Evaluation Metrics.}
For prefill reuse, we report task accuracy and time to first token (TTFT), where lower TTFT is better. For collaborative speculative decoding, we report generation throughput and MAT.

Detailed hyperparameters for MAReuse and all baselines, including recomputation ratios, filter-layer choices, retrieval anchors, draft budgets, and tree configurations, are provided in the supplementary material.

\subsubsection{Decoding Components}
Figure~\ref{fig:ablation-components} shows that the logits-cache tree is the foundation of MAReuse-D: removing it causes the largest drop, from 130.69 to 72.42 tokens/s and from 4.384 to 2.19 MAT, because it preserves draft coverage when retrieval is weak. The local and role-aware global indices are also indispensable: removing them lowers throughput to 105.71 and 122.33 tokens/s, respectively. These results show that local cross-agent reuse and global role-aware reuse complement each other, jointly forming an integrated draft mechanism with the logits-cache tree.

\section{Conclusion}

Overall, the results show that multi-agent inference contains exploitable redundancy beyond repeated prompt prefixes. By correcting reused KV states during prefill and turning agent histories into verifiable drafts during decoding, MAReuse converts both shared context and recurring generation patterns into practical acceleration opportunities. Across tasks, these gains indicate that reuse can accelerate the inference pipeline while preserving quality in most settings.
